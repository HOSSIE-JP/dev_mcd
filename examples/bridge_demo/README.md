# SGDK風ブリッジ追加APIのサンプル

`make bridge` で `dist/bridge_demo.cue` / `bridge_demo.iso` を生成します。
通常の日本版メガCD＋メガドライブ、NTSC 320×224向けです。

| 操作 | 確認する機能 |
|---|---|
| 方向キー | Plane Bのみを上下左右にスクロール。Plane Aの文字は固定 |
| A / B | 背景パレットを45フレームで暗転／復帰 |
| C | パレット3の文字色を変更。即時パレット変更は進行中のフェードを終了 |
| START | IMAGE.MIMをCDからWord RAMへ非同期ロード |

タイル2個を `MCD_loadTiles()` で転送し、属性付きタイルマップを
`MCD_setTileMapRect()` で構成します。文字の高優先度、押した瞬間の入力、
フレームカウンタ、パレット範囲フェードも使用しています。
STARTのロード中にも方向キー・A/Bで描画と入力が動き、完了時に
`CD IMAGE READY IN WORD RAM` へ変わることを確認します。
同時に右上のマーカーが動き続けることを確認してください。

`python3 -m unittest discover -s tests -p test_bridge.py -v` は
実装本体をホストのVDPポートモデルに接続し、タイル／マップ境界、
パレット範囲・フェード、入力エッジ、フレーム中のIPC完了を検査します。
ホスト検査は実機の表示タイミングやCDシークの確認を代替しません。

手元の日本版BIOSを使ったエミュレーター検査は、Linuxで次のように実行できます。
コアの準備は[セットアップ](../../docs/setup.md#biosとエミュレータ)を参照してください。

```sh
python3 tools/bridge_smoke.py --bios /path/to/bios_CD_J.bin
```

実際のCUEをGenesis Plus GXで起動し、画素と入力・ゲーム内状態を検査します。
結果は`build/bridge-smoke/report.json`、スクロール・フェード・CD読込後の画面は同フォルダーのPNGです。
画面の変化、固定文字、45フレームを越えた長押しがフェードを再発火しないこと、
フェードとスクロールの最中にCD読込が完了することを確認します。
BIOS画面やセーブステートは出力しません。これはエミュレーターでの検査で、実機性能の検証ではありません。

このサンプルは基礎API専用です。ノベルエンジンは別のVRAM割当で
日本語フォント・立ち絵を扱うため、その描画中にこのサンプルのタイルを
追加転送しないでください。
