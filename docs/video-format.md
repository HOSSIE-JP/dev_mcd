# MTV1形式（試作v1）

ビッグエンディアン、ISO9660 Mode 1内の連続した1ファイル。
ファイル名例 `MOVIE.MTV;1`。各レコードは2バイト境界に詰め、ファイル末尾だけを
2048バイト境界までゼロ詰めする。1フレームごとにCDセクタへ丸めない。

## ファイルヘッダ

先頭2048バイト。64バイト目以降はゼロ。

| オフセット | 型 | 意味 |
|---:|---|---|
| 0 | 4 bytes | ASCII `MTV1` |
| 4 | u16 | version=1 |
| 6 | u16 | header_bytes=2048 |
| 8, 10 | u16 × 2 | 表示枠の幅・高さ。8の倍数、最大320×224 |
| 12, 14 | u16 × 2 | FPS分子・分母。例7.5fpsは15/2 |
| 16 | u32 | フレーム数 |
| 20 | u32 | 時刻単位・PCMサンプルレート=16000 |
| 24 | u32 | 総音声サンプル数。動画の総尺を表す |
| 28 | u32 | 最大レコードバイト数。上限32768 |
| 32 | u16 | 辞書タイル数上限、1～512 |
| 34 | u16 | flags=1: RF5C164用PCM8モノラル |
| 36～59 | 24 bytes | 予約、ゼロ |
| 60 | u32 | bytes 0～59 のIEEE CRC32 |
| 64～2047 | bytes | ゼロ |

このパーサの上限は2時間、FPS分子1～30、分母1～2。
エンコーダが用意するプリセットだけが今回の評価対象。
`ceil(total_samples * fps_num / (rate * fps_den))` がframe_countに一致する。

## フレームレコード

すべて独立して復元できる。直前フレームの辞書・画像・パレットに依存しない。

| オフセット | 型 | 意味 |
|---:|---|---|
| 0 | 4 bytes | ASCII `FRM1` |
| 4 | u32 | ヘッダを含むレコード長、偶数 |
| 8 | u32 | 0始まりの連番 |
| 12 | u32 | PTS、16000サンプル/秒の時刻 |
| 16 | u16 | このフレームの辞書タイル数 |
| 18 | u16 | 配置表セル数 `(width/8)*(height/8)` |
| 20 | u32 | このレコードに含む音声サンプル数 |
| 24 | u32 | 後続ペイロード全体のIEEE CRC32。偶数化の末尾ゼロを含む |
| 28 | u32 | flags=0 |
| 32 | u16 × 16 | MDパレット。`0000 BBB0 GGG0 RRR0`。色0は黒 |
| 64 | 32 bytes × N | 8×8・4bppタイル辞書。左画素が上位ニブル、各行4バイト |
| 続き | u16 × cells | 行優先のローカル辞書番号。反転・パレットフラグなし |
| 続き | u8 × audio_samples | RF5C164用PCM。bit7=正、下位7bit=絶対値。`FF`禁止 |
| 末尾 | 0～1 byte | 偶数長にするゼロ詰め |

レコードサイズは `32 + 32 + 32*N + 2*cells + audio_samples` を偶数へ丸めた値。
PTSは `floor(sequence * rate * fps_den / fps_num)`。
音声範囲は `[PTS, min(next_PTS,total_samples))`。各レコードは隙間なく音声を連結する。
最後の動画フレームは次の定刻まで延ばさず、total_samples時点で終了する。
音声がない元動画にも同じ長さの無音PCMを入れ、時刻の意味を統一する。

PCM変換では、正側の最大絶対値を126に制限し、ループマーカーFFとの衝突を避ける。
負側の127は7Fで表せる。ゼロは80。プレビュー音声もこの量子化後PCMから復元する。

## ストリームAPIの寿命

`MCDV_init`には呼び出し側が所有する32KiB以上のscratchを渡す。
`MCDV_feed`は入力の消費バイト数を返す。`ready=1`で停止するため、未消費部分を保持する。
次のセクタやPRGキャッシュにまたがっても同じAPIで処理できる。
`frame`の各ポインタはscratch内を参照し、`MCDV_release`後は無効になる。
**PCM／Word RAMへのコピー、そこからの必要な転送が終わる前にreleaseしない。**

`MCDV_parseFrame`とアップロードプランは、検査済みヘッダと検査済みフレームを前提とする。
ディスク終端で`MCDV_finish`を呼び、フレーム数・ファイルの末尾パディングまで確認する。
ボディCRCを無効にしても、サイズ、番号、PTS、辞書番号、パレット、PCMマーカーの検査は行う。

CRC32の現在のC実装は小さなビット演算版。ホスト検証では常に有効。
ターゲットの毎フレーム処理ではCPU負荷を測るまで有効化しない。
CDのエラー訂正を使用し、境界検査は常に有効にする。実機で必要ならテーブル方式を計測して採用する。

## VDP転送プラン

`video_upload.c`はVDPレジスタに触れず、転送元・転送先・長さを順に返す。
タイル辞書→表示枠の各配置表行→非表示側パレット、の順。
バイト予算が不足すれば0を返し、次のVBlankまで待つ。
配置表行のscratchは再利用されるので、次の呼び出しまでに転送元を消費する。
DMAをキュー化する場合は、必要なデータを寿命が保証されたバウンス領域にコピーする。

完了後、音声の再生位置がPTSに達したVBlankでPlane Bのベースを切り替える。
転送完了と表示時刻は別の条件。コードブックを展開して320×224のフレームバッファを作る処理は不要。
